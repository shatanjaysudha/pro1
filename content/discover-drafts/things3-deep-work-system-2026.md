# Things 3 Deep Work Setup: The 2026 System That Holds Up

## Hook
Most task systems fail under pressure because they optimize for capture, not execution. Things 3 is powerful when you use it as an execution architecture, not a storage system. This setup is designed for real weeks with interruptions, meetings, and shifting priorities.

## The Architecture
Use these layers:
- **Areas:** long-term responsibility buckets.
- **Projects:** outcomes with clear finish lines.
- **Next actions:** execution units that can be done in one focused session.

Never store vague tasks without a next-action definition.

## Setup Rules
1. Area names reflect operating domains (Work, Learning, Admin, Personal).
2. Projects include one explicit completion condition.
3. Every active project has at least one next action.
4. Deadlines are reserved for true commitments only.
5. Today list is constrained to realistic bandwidth.

## Weekly Review Protocol
Run one 30-minute review every week.

Checklist:
- clear all inbox items,
- close finished projects,
- add next actions for active projects,
- remove stale tasks,
- plan deep-work blocks for priority projects.

This is the compounding layer. Without it, Things 3 becomes a graveyard.

## Daily Execution Protocol
Morning:
- choose 1 strategic task,
- choose 2 support tasks,
- block one deep-work window.

Afternoon:
- process communication in one batch,
- update project status,
- schedule carry-over intentionally.

No open-loop task should survive without a decision.

## Deep Work Integration
For deep work, tag tasks with:
- `deep` for high-cognitive tasks,
- `shallow` for admin tasks,
- `waiting` for dependency tasks.

Only schedule `deep` tasks in your protected blocks.

## Common Failure Modes
- Overusing deadlines.
- Too many someday tasks without review.
- Project names that describe activity, not outcomes.
- Large tasks with no concrete next action.

Fix these first before adding complexity.
